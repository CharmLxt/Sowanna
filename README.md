Sowanna. Версия 0.2.0. Автор CharmLxt (PyPI: CharmLxt, email: reception.mailspypi@gmail.com). Ссылка на GitHub: https://github.com/CharmLxt/Sowanna.



Sowanna — это библиотека, которая позволяет вызывать методы C# из Python так, будто они Python-функции. Вы пишете C#-проект в своей IDE, компилируете его в обычную .dll, описываете проект в маленьком JSON-манифесте с расширением .pycsh, и дальше из Python вызываете методы по имени. Ядро бриджа написано на C# — это Bridge.exe, который загружает вашу .dll через рефлексию и держит её в памяти, обмениваясь с Python короткими JSON-сообщениями по stdin/stdout. Никаких сторонних зависимостей в Python, никакого pythonnet, никакого ctypes — только стандартная библиотека и запущенный Bridge.exe.



В версии 0.2.0 мы сделали акцент на производительность и работу с тяжелыми данными. Протокол обмена был оптимизирован для передачи больших Base64-строк (например, сжатых кадров экрана или изображений) без лишнего экранирования, что снижает нагрузку на память и ускоряет обработку. Также добавлен полноценный двунаправленный коллбэк: если в вашем C#-классе объявить публичное статическое поле CallbackHandler типа Func<string, object\[], object?>, Bridge автоматически подставит туда свой обработчик. Теперь C# может не только возвращать результат в Python, но и вызывать Python-функции в процессе своей работы (например, запрашивать данные для логирования или обрабатывать события). Эта версия полностью совместима с удаленным управлением экраном (проект Monogrammer).



Как это работает. В папке вашего C#-проекта рядом с .csproj лежит файл sowanna.pycsh — манифест в формате JSON. В нём указано имя проекта, версия, имя скомпилированной .dll, полное имя класса-точки-входа и опционально список методов. Python-сторона Sowanna читает манифест, находит .dll, поднимает Bridge.exe и передаёт в него путь к .dll и имя класса. Bridge загружает сборку, находит класс и вызывает запрошенный метод через reflection.



Что нужно установить. Python 3.8+ и .NET SDK 6.0 или новее. Один раз соберите Bridge.exe: cd Sowanna\\bridge, потом .\\build.ps1. Скрипт вызовет dotnet publish и положит Bridge.exe в sowanna\_bridge. Если вы хотите использовать Monogrammer или другие тяжелые C#-модули, их .dll собираются отдельно (например, через dotnet build) и кладутся в ту же папку или указываются в манифесте. Framework-dependent сборка позволяет Bridge.exe весить всего около 500 КБ, не засоряя ваш проект и репозиторий мегабайтами системных библиотек.



Три фасада. VovSC (Value of vectors Sharp Code) — универсальный, режим auto: держит один долгоживущий Bridge-процесс, перезапускает его при падении. UniPlcahCSC (Unical Python lite code and heavy C Sharp Code) — режим «всегда новый процесс», с health-check и circuit breaker. minpyAovCS (minimal python and Overall C Sharp) — C#-первый дизайн: вы даёте путь к .dll и полное имя класса, фасад сам создаёт рядом манифест и предоставляет доступ по имени метода. Все три фасада используют один engine и один Bridge.exe, различие только в политике жизненного цикла.



Чего Sowanna не делает. Не компилирует ваш C# из Python (компилируйте в своей IDE). Не поддерживает async/await на C#-стороне (только синхронные методы). Не поддерживает generics и перегрузки методов с одинаковыми именами (будет выброшена ошибка AmbiguousMatch).
