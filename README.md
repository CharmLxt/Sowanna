Sowanna — это библиотека, которая позволяет вызывать методы C# из Python так, будто они Python-функции. Вы пишете C#-проект в своей IDE (Dev C++ Embarcadero, Visual Studio, Rider, что угодно, что умеет .NET), компилируете его в обычную .dll, описываете проект в маленьком JSON-манифесте с расширением .pycsh, и дальше из Python вызываете методы по имени. Ядро бриджа написано на C# — это Bridge.exe, который загружает вашу .dll через рефлексию и держит её в памяти, обмениваясь с Python короткими JSON-сообщениями по stdin/stdout. Никаких сторонних зависимостей в Python, никакого pythonnet, никакого ctypes — только стандартная библиотека и запущенный Bridge.exe.

Как это работает. В папке вашего C#-проекта рядом с .csproj лежит файл sowanna.pycsh — это манифест в формате JSON. В нём указано имя проекта, версия, имя скомпилированной .dll, полное имя класса-точки-входа (namespace.class) и опционально список методов с описанием аргументов. Python-сторона Sowanna читает манифест, находит .dll, поднимает Bridge.exe и передаёт в него путь к .dll и имя класса. Bridge загружает сборку, находит класс и дальше на каждый запрос вызывает указанный статический метод через reflection. Каждый запрос — одна строка JSON вида {"id": 1, "method": "Add", "args": [2, 3]} и ответ тоже одна строка. Bridge.exe не перезапускается между вызовами в пределах одной сессии.

Обратный вызов Python из C#. В 0.1.0 добавлен настоящий двунаправленный канал. Если в вашем entry-классе объявить публичное статическое поле CallbackHandler типа Func<string, object[], object?>, Bridge.exe автоматически подставит туда свой обработчик после загрузки сборки. Дальше в любом C#-методе вы вызываете CallbackHandler("some_name", new object[]{a, b}) — Bridge отправляет в Python сообщение callback, Python находит зарегистрированный callback по имени (через v.register_callback("some_name", func)), вызывает его, отправляет обратно результат (или ошибку), Bridge получает и возвращает C#-методу. Всё это происходит в том же процессе и в том же потоке, без дополнительных pipe. Пример из HelloWorld: C#-метод CallPythonSum(a, b) вызывает Python-callback "sum" и возвращает его результат. Python-сторона регистрирует v.register_callback("sum", lambda a, b: a + b), и v.CallPythonSum(10, 20) возвращает 30. Протокол обратно совместим: старые сообщения без поля kind считаются обычными response, добавление callback не ломает ничего, что уже работало.

Генератор .pyi стабов. Команда sowanna stubs path\to\sowanna.pycsh читает манифест и создаёт рядом файл .pyi с описанием класса и всех методов, с маппингом C#-типов в Python-типы (int → int, string → str, int[] → List[int], bool → bool, void → None, double[] → List[float], всё неизвестное → Any). Если положить этот .pyi рядом с .py-обёрткой, VS Code и PyCharm начнут подсказывать автодополнение для ваших методов, даже если реально они вызываются через getattr. Опция --output указывает явный путь, --class-name задаёт имя класса в стабах (по умолчанию берётся последний сегмент entry_class, то есть "Entry" для "HelloWorld.Entry"). Файл .pyi — это чистый generated code, регенерируется одной командой, никакой ручной правки не требует.

Self-contained publish. По умолчанию Bridge собирается framework-dependent: Bridge.exe весит около 500 КБ, но требует установленного .NET 6 Runtime на машине, где Sowanna запускается. Если вы хотите распространять Sowanna-приложение на машины без .NET Runtime, соберите Bridge один раз с флагом .\build.ps1 -SelfContained. Тогда .exe вырастет примерно до 60-70 МБ, но будет работать на любой Windows-машине без установленного .NET. Флаг -SingleFile дополнительно упаковывает всё в один .exe (для 0.1.0 не рекомендую: reflection-based загрузка вашей .dll работает, но сам Bridge.exe станет чуть медленнее стартовать). Флаг -Runtime задаёт RID, по умолчанию win-x64, доступны win-x86, win-arm64, linux-x64 и другие, но примеры в репозитории проверялись только под Windows.

Три фасада. VovSC (Value of vectors Sharp Code) — универсальный, режим auto: держит один долгоживущий Bridge-процесс, если процесс умер — перезапускает. Хорош для интерактивной работы. UniPlcahCSC (Unical Python lite code and heavy C Sharp Code) — режим «всегда новый процесс», с health-check, рестартом и circuit breaker: после max_failures подряд переходит в «открытое» состояние и отказывается запускать новые вызовы до истечения cooldown секунд. Подходит для пакетной обработки, где один упавший C#-метод не должен уронить всю сессию. minpyAovCS (minimal python and Overall C Sharp) — C#-первый дизайн: вы даёте путь к .dll и полное имя класса, фасад сам создаёт рядом манифест и предоставляет доступ по имени метода. Все три фасада используют один engine и один Bridge.exe, различие только в политике жизненного цикла.

Что нужно установить. Python 3.8+ и .NET SDK 6.0 или новее (сейчас Sowanna проверялась на SDK 6.0.428). Один раз соберите Bridge.exe: cd Sowanna\bridge, потом .\build.ps1. Скрипт вызовет dotnet publish и положит Bridge.exe, Bridge.dll, Bridge.runtimeconfig.json и Bridge.deps.json в sowanna_bridge, откуда Sowanna автоматически их подхватит. Для self-contained версии: .\build.ps1 -SelfContained.

Для чего это. Для случаев, когда у вас уже есть тяжёлая C#-библиотека (математика, обработка изображений, работа с железом, что-то из .NET-экосистемы), и вы не хотите переписывать её на Python. Или для случаев, когда C#-часть удобнее писать отдельно в нормальной IDE, а Python остаётся оркестратором. Или для случаев, когда критичный участок нужно вынести в отдельный процесс с изоляцией — тогда UniPlcahCSC даёт вам автоматический рестарт и circuit breaker.

Чего Sowanna не делает. Не компилирует ваш C# из Python — компилируйте сами в своей IDE, это честнее и предсказуемее. Не поддерживает async/await на C#-стороне в 0.1.0 — только синхронные статические методы. Не поддерживает generics на стороне Python — только конкретные перегрузки методов с известными аргументами (и overloads тоже не поддерживаются: если у класса два метода Add с разными аргументами, будет ошибка AmbiguousMatch). Не делает автоматический рестарт Bridge.exe посреди callback-сессии (если процесс умер во время callback, Python получит BridgeCrashedError и увидит stderr от Bridge).

Для красивых сообщений Sowanna мягко интегрируется с CharmPkk (как и все остальные наши библиотеки): если CharmPkk установлен, баннеры, таблицы и ошибки будут цветными, если нет — обычный print.
